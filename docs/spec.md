# ノボル 仕様書（v2）

神社参拝を記録するスマホ向けWebアプリ。
**アプリ内は一つ一つの神社の詳細**、**別途用意する note は参拝作法など全体の話**、という役割分担にする。

- DB定義: [`supabase/schema.sql`](../supabase/schema.sql)
- セットアップ手順: [`README.md`](../README.md)

---

## 1. 使われ方

| 場面 | 頻度 | すること |
|---|---|---|
| 参拝した直後 | メイン | 参拝記録を付ける |
| 気が向いたとき | サブ | 神社を探す・調べる / マップで自分の参拝を見返す |
| 時々 | サブ | みんなでの達成状況・ユーザー数を眺める |

## 2. 画面構成

下部タブは5つ：**近くの神社 ／ マップ ／ 探す ／ 一覧 ／ マイページ**
（記録画面・神社詳細・記録詳細・情報提供フォームはタブなしの子画面）

### 2.1 近くの神社（`/`・ホーム）
1. 開くとGPSで位置取得を開始（待たずに操作できる）
2. **近くの神社**を距離順に表示（3km以内・最大8件。端末に保存した神社一覧から計算するので圏外でも動く）
   - 行をタップ → 記録画面（その神社を選んだ状態）
   - 行の右の「詳しく」→ 神社詳細
   - 位置が取れない場合・遠くの神社は上の検索欄から探す（結果の行も同じ動き）
   - リストにない場合は「神社の追加を申請」→ `shrine_requests`
   - ログインしていなくても一覧・詳細は見られる（記録画面でログインを求める）

### 2.1.1 記録画面（`/record/:shrineId`）
1. 神社を選んだ状態で開く（近くの神社の行・神社詳細の「ここを記録する」から）。左上の「‹」で戻る
   - 以前の `/?shrine=ID` のリンクはこの画面へ転送する
2. 位置は「現地で記録」の判定にだけ使う（待たずに入力できる）
3. 入力項目
   | 項目 | 備考 |
   |---|---|
   | 参拝日 | 既定は今日。後から変更可 |
   | 感動の温度 | 0〜100。5段階ラベル（静かな気づき〜魂が震えた） |
   | この記録を見られる人 | 「みんな」／「自分だけ」（`is_public`）。選んだ側で何がどこに載るかを下に書く |
   | みんなへのメモ | `public_memo`。記録が「みんな」のときだけ神社のページに載る |
   | 自分だけのメモ | `private_memo`。別テーブルで、記録を公開しても本人以外は読めない |
   | 次回へのメモ | |
   | 写真 | 最大10枚。長辺1200px・100KB以下に圧縮。1枚ずつタグを付ける（下の4） |

   - 公開範囲を先に選び、メモは2つとも常に表示する（タブで隠さない）
4. 写真のタグ（写真があるときだけ）
   - 「記録する」を押すと、写真を1枚ずつ大きく表示し「何が写っていますか？」と聞く
   - タグは **鳥居・狛犬・本殿・御朱印・案内板・その他** から1つ（`photos.tag`）。最初は「その他」が選ばれている
   - タグを押すと次の写真へ。最後の写真のタグを押すと保存する。「‹ 前の写真」「‹ 入力に戻る」で戻れる
   - タグは記録詳細の「編集」から付け直せる（本人は `photos` のタグの列だけ更新できる）
5. 保存
   - 端末に保存 → 電波があれば即送信、なければ**電波が戻ったら自動送信**
   - 未送信の記録は一覧に「未送信」と表示
   - 初めての参拝者だった場合「あなたがこの神社の最初の参拝者です」（あとから送れた記録も同じ）
   - 保存したらすぐ来た画面（近くの神社・神社詳細）へ戻り、「記録完了！」を小さく表示（3秒ほどで消える）
     - 電波がなく端末に保存したときは「記録完了！　電波が戻ったら送信します」、最初の参拝者だったときはその旨も添える
6. 画面下部に note「参拝作法」へのリンク（`guide_links.context = 'etiquette'`）

### 2.2 マップ（`/map`）
- 地図: Leaflet + OSMタイル。ピンが多い場所はまとめて件数表示（supercluster）
- 表示切替: **自分の参拝**（既定） ／ 自分の未参拝 ／ まだ誰も行っていない
- 自分の参拝ピンをタップ → 神社名・参拝日・回数 → 記録詳細へ
- 他のピンをタップ → 神社詳細へ

### 2.3 探す（`/search`）
- 「神社名で探す」「ご祭神で探す」を切り替える
- 神社名・読み仮名で検索（端末の一覧から即時検索）
  - 「八幡 世田谷」のように空白で区切ると、2語目以降は市区町村・地名・都道府県にも当てはめる（どれか1語は名前に当たること）
  - 結果の各行に「都道府県 市区町村 地名」を出し、同じ名前の神社を見分けられるようにする（記録画面の神社選択も同じ）
- ご祭神で検索：表記の違い（須佐之男命・スサノオ → 素戔嗚尊）を吸収する（[`src/lib/deities.js`](../src/lib/deities.js)）。神社詳細のご祭神をタップしても来られる（`/search?deity=…`）
- 都道府県で絞り込み、「まだ誰も行っていない」で絞り込み
- 全体の達成状況：「全国 ○○社中 ○○社に参拝済み（○%）」、都道府県別の達成率

### 2.4 神社詳細（`/shrine/:id`）
上から次の順に並べる。

| 区分 | 項目 |
|---|---|
| 名前 | 名前・読み仮名・場所（都道府県 市区町村 地名） |
| 写真 | **本殿**の写真（いちばん新しいもの）を1枚大きく表示。その下にタグのボタンを件数付きで並べる（0件のタグは出さない）。タグを押すとそのタグの写真を新しい順に並べ、写真を押すと拡大。本殿の写真がなければタグのボタンだけ。公開記録の写真だけを使う |
| 参拝の情報 | 拝観時間・御朱印（横に note「御朱印とは」リンク）・御朱印メモ ← 現地でいちばん知りたいこと |
| 見どころ | 文章 |
| 基本情報 | 住所・ご祭神（表記をそろえて表示、タップで同じ神様の神社を検索）・ご利益・社格・創建・例祭 |
| 由緒 | 神話・創建の背景など（文章。列は `features`）。出典表示 |
| アクセス | 最寄り駅（距離・徒歩目安）・最寄りバス停・駐車場・アクセス補足 |
| 自分 | 自分の参拝回数・過去の記録 |
| みんな | 「この神社を訪れた人：○人」・公開記録の一覧 |

- 創建・例祭は「伝・景行天皇の御代」「毎年9月15日」のように書くことが多いので、日付ではなく文字で持つ

- 「情報を追加・訂正」ボタン → 項目ごとの入力フォーム → `shrine_edits`
- 「ここを記録する」ボタン → 記録画面（神社選択済み）
- 徒歩の目安は 80m/分 で直線距離から計算し「約」を付ける

### 2.5 一覧（`/records`）
- 自分の記録を新しい順に表示
- 絞り込み：すべて ／ 感動大（75以上） ／ 写真あり ／ 公開 ／ 非公開 ／ 未送信
- タップで記録詳細（編集・削除）

### 2.6 マイページ（`/profile`）
- 未ログイン時: Googleでログイン
- 参拝数・参拝した神社の数・感動平均・称号
- **参拝の手引き**: note 記事リンクの一覧（`guide_links.context = 'general'`）
- **アプリへのご意見・ご要望**（`/feedback`）: どの画面についてか（近くの神社・記録画面・神社詳細・マップ・探す・一覧・マイページ・その他）を1つ選び、自由に書いて送る（`feedback`。2000字まで、ログインが必要）
  - 読めるのは管理者だけ。マイページの「ご意見・ご要望の確認」（`/admin/feedback`）で新しい順に読み、「対応済みにする」で未対応の一覧から外す
  - 情報提供を止められたユーザーは送れない
- ログアウト

### 2.7 ユーザー数の表示
押しつけず静かに見せる。

- ホーム（近くの神社）上部に小さく「この30日で、全国 ○人 が参拝しています」
  - 人数は「**過去30日（今日を含む）に1社以上参拝したユーザーの人数**」（参拝日で判定。`get_app_stats().recent_visitors`）
- 神社詳細に「この神社を訪れた人：○人」（`shrines.visitor_count`）
- 集計関数は数字だけを返し、誰がいるかは見えない

### 2.8 称号
参拝した神社の数（重複なし）で決まる。
0社 参拝初心者 → 5社 氏子 → 15社 神主見習い → 30社 神主 → 50社 大神主 → 100社 神域の訪人

バッジは判定の根拠がないものを削除し、必要になったら改めて設計する。

### 2.9 削除する機能
- おみくじ読み取り（Gemini）
- 神様からのメッセージ（Gemini）

→ Gemini を使わなくなるため `VITE_GEMINI_API_KEY` も不要。

## 3. 神社マスタ

### 3.1 対象範囲
- 含める: 神社、小さな社・祠
- 含めない: **境内社**（ほかの神社の敷地内にある社）
- 規模の見込み: 10万社前後

### 3.2 データ元と項目

| 項目 | 取得元 | 備考 |
|---|---|---|
| 名前・位置 | OSM（`amenity=place_of_worship` + `religion=shinto`） | 名前なしは「名称不明の社（地名）」 |
| 読み仮名 | OSM `name:ja-Hira` / Wikidata | |
| 都道府県・市区町村・住所 | OSM の住所タグ、なければ行政区域から判定。住所が空なら国土地理院の逆ジオコーダーで「市区町村＋町字」（`--gsi-address`） | 番地までは入らない |
| 地名（`locality`） | OSM の住所タグ（`addr:quarter` など）、なければ3km以内で最も近い地名（`place=*`） | 同じ名前の神社を見分ける用。市区町村と同じなら空 |
| ご祭神 | Wikidata、情報提供 | 表記をそろえて入れる（3.5） |
| ご利益・社格 | Wikidata、情報提供 | 小さな社は空欄が多い |
| 最寄り駅・バス停 | OSM の `railway=station` / `highway=bus_stop` から**自動計算** | 直線距離 |
| 駐車場 | OSM の近くの `amenity=parking`（200m以内）→「近くにあり」、それ以外は情報提供 | 専用あり／近くにあり／なし／不明 |
| 御朱印 | 情報提供のみ | あり／書き置きのみ／なし／不明 |
| 由緒（`features`） | Wikipedia 要約（有名社）、手書き、情報提供 | Wikipedia 由来は CC BY-SA の出典表示が必要 |
| 創建・例祭・拝観時間・見どころ | 情報提供のみ | 文字で入れる |

- 地図データの出典表示: 「© OpenStreetMap contributors」（ODbL）をマップ画面と神社詳細に表示

### 3.3 境内社の除外
OSM で神社の敷地（way/relation のポリゴン）が登録されている場合、その内側にある別の神社ポイントを除外する。
敷地が登録されていない神社では除外できないため、残ったものは情報提供（「境内社です」報告）で非表示（`status = 'hidden'`）にする。

### 3.4 取り込み処理（`scripts/import-shrines.mjs`、使い方は [`scripts/README.md`](../scripts/README.md)）
1. Overpass API から**都道府県ごと**に神社・祠、駅、バス停、駐車場、地名、市区町村の境界を取得（結果は `scripts/.cache/` に保存し再利用）
2. 境内社の除外、最寄り駅・バス停・駐車場、市区町村の判定、名前のない社の命名
3. Wikidata（`wikidata` タグがある社）からご祭神（P825）・読み仮名（P1814）、Wikipedia から冒頭の要約を取得
4. `import_shrines()` で `shrines` に反映（キーは `osm_ref`）。service_role キーで実行
   - 名前・位置・駅などOSM由来の列は毎回上書き
   - ご祭神・駐車場・御朱印・由緒など**情報提供できる列は、空のときだけ**埋める（ユーザーの情報を消さない）
   - OSMから消えた神社は自動では消さない（必要なら `status = 'hidden'`）
5. 軽い一覧ファイルを生成して Storage（`public-data`）に置き、`app_meta.shrine_index_version` を更新

### 3.5 ご祭神の表記
- [`src/lib/deities.js`](../src/lib/deities.js) に、よく祀られる神様の代表の表記と別の書き方の辞書を持つ（例: 素戔嗚尊 ← 須佐之男命・素盞嗚尊・スサノオ）
- 比べるときは、全角半角・旧字（國→国 など）・「之」「の」・「々」・末尾の「命／尊／神／大神／大御神／公」の違いを吸収する
- 情報提供の入力は送る前に代表の表記にそろえ、何をどう直すかを入力欄の下に出す。取り込み（Wikidata）も同じ
- 辞書にない神様は書かれたまま。すでに DB に入っている古い表記は、表示時と一覧ファイル作成時にそろえる（DB の値はそのまま）
- 神様を増やすときは `DEITIES` に1行足し、一覧ファイルを作り直す

## 4. 読み込みの工夫

### 4.1 2段階に分ける
| 種類 | 内容 | サイズ目安 | 取り方 |
|---|---|---|---|
| 軽い一覧 | id・名前・読み仮名・緯度経度・都道府県・市区町村・地名・ご祭神・誰か参拝済みか | 10万件で約5MB / gzip後 約1.5MB（見込み） | Storage の静的ファイル `shrines-index.<version>.json.gz` |
| 詳細 | 住所・ご祭神・アクセス・由緒など | 1件数KB | 神社詳細を開いたときに `shrines` から1件取得 |

- 軽い一覧は API（1回1000件まで）ではなく**静的ファイル1つ**で配信する（速く、DBに負荷がかからない）
- 形式は列ごとの配列にしてサイズを抑える（例: `{"v":12,"id":[...],"name":[...],"lat":[...],...}`）

### 4.2 タイミング
1. 初回起動: 画面はすぐ表示し、一覧ファイルは裏で取得 → IndexedDB に保存
   - 取得中は検索・近くの候補に「神社一覧を準備中…」と表示。ホームの検索はサーバー検索で代替
2. 2回目以降: 端末の一覧を即使用。起動時に `app_meta.shrine_index_version` だけ確認し、変わっていたら裏で更新
3. 「誰も行っていない」状態は一覧ファイルに含めるが、更新頻度が高いため、マップ・探す画面を開いたときに `shrines(id, first_visited_on)` の差分（前回取得以降に変わったもの）を取得して上書きする

### 4.3 PWA
- `vite-plugin-pwa` でホーム画面に追加できるようにし、アプリ本体・一覧ファイルをキャッシュ
- 地図タイルは見た範囲だけキャッシュ（オフラインで全国の地図は持たない）

## 5. 記録の信頼性（GPS）

- **GPSは記録の条件にしない**。山奥・木の下・谷間では誤差が大きく、回線がないと位置取得に時間がかかるため
- 位置が取れて神社から**半径300m以内**（誤差込み）なら `onsite = true`（「現地で記録」の小さな印）
- みんなでの達成数には印の有無にかかわらず全記録を数える
  - 将来不正が問題になったら、`onsite` の記録だけで集計し直せる
- **オフライン保存**: 記録と写真をいったん IndexedDB に保存し、すぐ送信を試みる
  - 送れなかったら「未送信」として残し、電波が戻ったとき・アプリ起動時・1分ごとに再送
  - 記録のIDを端末で採番して送るので、再送しても二重登録されない

## 6. みんなで全社参拝

- `shrines.first_visited_on` が NULL ＝ まだ誰も行っていない
- `records` の追加・削除時にトリガーで `record_count` / `visitor_count` / `first_visited_on` を再計算
- 非公開記録も達成数には含める（数だけ集計し、誰が行ったかは出さない）
- 表示: 全国の達成率、都道府県別の達成率（`get_prefecture_progress()`）、マップの「まだ誰も行っていない」ピン
- 最初の参拝者になったときのメッセージ

## 7. 情報提供

- 対象項目: 住所・読み仮名・ご祭神・ご利益・社格・創建・例祭・拝観時間・見どころ・最寄り駅・バス停・アクセス補足・駐車場・御朱印・御朱印のメモ・由緒
- 画面は神社詳細と同じ並びで全項目を表示し、変えた項目だけをまとめて送る（`shrine_edits` に項目ごとに1行）
- 御朱印は「直書き」「書き置き」を両方選べる（`direct_only` / `written_only` / `both`。旧データの `available` は「あり」と表示）
- 最寄り駅・バス停は取り込み時に OSM から自動で入るが、情報提供されたら「〇〇駅 徒歩10分」などの文字をそのまま表示し、以後の取り込みで上書きしない（`*_by_user`）。空にすると次の取り込みで OSM の値に戻る
- 「最後に提供された内容をすぐ採用し、履歴（`shrine_edits`）を残す」。承認制にはしない（管理者が全神社の真偽を確かめるのは難しく、承認待ちが溜まると情報が増えないため）
- `shrines` はユーザーから直接更新できず、`shrine_edits` の追加時にトリガーが反映する。そのとき変更前の値を `old_value` に残す
- いたずら対策は「後から戻せる」ことで行う（管理者の「情報提供の確認」`/admin/edits`）
  - 最近の変更を新しい順に「変更前 → 変更後」で表示。真偽は確かめず、明らかないたずらだけ「元に戻す」（`revert_shrine_edit()`）
  - 同じ項目に後から別の変更があるときは戻さない（新しい変更から順に戻す）
  - 提供者ごとに絞り込み、「すべて元に戻す」（`revert_user_edits()`）、「情報提供を止める」（`set_editor_banned()` → `banned_editors`）ができる。止められた人は情報提供・申請を送れない（RLS）
- 神社の追加申請（`kind = 'add'`）と、境内社・重複など一覧から外す報告（`kind = 'hide'`）は `shrine_requests` に入り、管理者が確認して反映する
  - 管理者は `admins` テーブルに登録したユーザー。マイページの「申請の確認」（`/admin/requests`）で承認・却下する
  - 承認・却下は `review_shrine_request()` で行う（追加なら `shrines` に1件追加、外す報告なら `status = 'hidden'`）
  - 承認後、管理者画面の「神社一覧を更新する」で一覧ファイルを作り直し、`app_meta.shrine_index_version` を更新する

## 8. 参拝の手引き（note リンク）

- `guide_links` テーブルで管理（Supabase ダッシュボードから追加・並べ替え）
- `context` で表示場所を決める

| context | 表示場所 |
|---|---|

## 9. 技術構成

| 区分 | 採用 |
|---|---|
| フロント | React 18 + Vite + react-router-dom |
| 認証・DB・Storage | Supabase（Googleログイン） |
| 地図 | Leaflet + OSMタイル + supercluster |
| 端末保存 | IndexedDB（`idb-keyval` などの小さなライブラリ） |
| PWA | vite-plugin-pwa |
| 写真 | Storage の非公開バケット `photos`、署名付きURLで表示 |
| マップ画面 | 地図ライブラリが大きいため、マップを開いたときに読み込む |

環境変数: `VITE_SUPABASE_URL`、`VITE_SUPABASE_ANON_KEY`（Gemini は不要に）

### コード構成
| 場所 | 内容 |
|---|---|
| `src/pages/` | 画面 |
| `src/components/` | 共通部品（下部タブ、神社選択、写真、手引きリンクなど） |
| `src/hooks/` | アプリ全体の状態（ログイン、神社一覧、未送信の記録、トースト） |
| `src/lib/` | データ取得・計算（`indexCore.js` `geo.js` `constants.js` は取り込みスクリプトと共用） |
| `scripts/` | 神社マスタの取り込み |
| `supabase/schema.sql` | DB定義 |
| `tests/` | `npm test` で実行するテスト |
