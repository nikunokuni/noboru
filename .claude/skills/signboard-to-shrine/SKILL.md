# 案内板の写真から神社詳細の空欄を埋める

投稿された案内板の写真を読み、**空欄の項目だけ**を埋める。埋まっている項目は、案内板と食い違っていても書き換えない（報告だけする）。
書き込みは情報提供（`shrine_edits`）として入るので、管理者画面の「情報提供の確認」から1件ずつ元に戻せる。

## 決まりごと

- **空欄だけ埋める**。上書きはしない（`scripts/lib/signboard.mjs` の `planEdits` も、埋まっている項目は書かない）
- **由緒（`features`）は要約する**。案内板の文章を書き写さず、自分の言葉で 2〜4 文・400 字以内にまとめる。
  入れるのは「いつ・誰が・なぜ創建したか」「関連する神話・伝承」「遷座・合祀などの大きな出来事」。寄進者の名前の一覧、建立年月日の細部などは入れない
- **読めたことだけ書く**。かすれ・反射・崩し字で自信がないものは入れず、`note` に「〇〇は読めなかった」と書く。推測で埋めない。
  ほかの資料（Wikipedia など）や自分の知識で補わない。案内板に書いてあることだけ
- **対象は公開記録の写真だけ**（スクリプトが絞る）。写真や写っている人について、ほかの場所に書き出さない
- 書き込む前に、必ず下見（`apply` を `--write` なしで実行）の内容をユーザーに見せて OK をもらう

## 入れる項目

| 項目 | 書き方 |
|---|---|
| `name_kana` よみがな | 案内板にふりがながあるときだけ。ひらがなで（例: `ひかわじんじゃ`） |
| `deities` ご祭神 | 「、」区切り（例: `素戔嗚尊、櫛稲田姫命`）。表記はスクリプトがそろえる |
| `benefits` ご利益 | 配列。案内板に「ご神徳」「ご利益」として書かれたものだけ。なるべく次の言い方に寄せる: 縁結び・厄除け・開運・家内安全・商売繁盛・学業成就・合格祈願・安産・子授け・健康長寿・病気平癒・交通安全・仕事運・金運・必勝祈願・五穀豊穣・芸能上達・航海安全・火除け・縁切り（合わないものはそのまま） |
| `shrine_rank` 社格 | 例: `旧村社`、`式内社`。旧社格は「旧」を付ける |
| `founded` 創建 | 例: `伝・景行天皇の御代`、`天正18年（1590年）` |
| `annual_festival` 例祭 | 例: `毎年9月15日` |
| `honden_style` 本殿の様式 | 例: `一間社流造` |
| `highlights` 見どころ | 案内板にある御神木・文化財・境内社など。短く（例: `樹齢600年の大銀杏（市指定天然記念物）`） |
| `features` 由緒 | 上の「要約する」のとおり |

住所・拝観時間・駐車場・御朱印は案内板からは入れない。

## 手順

### 0. 準備（初回だけ）

- 環境変数 `SUPABASE_URL` と `SUPABASE_SERVICE_ROLE_KEY` が要る（`.env` か、クラウド環境のシークレット）。ないときは、ユーザーに設定してもらう。**キーをチャットに貼ってもらわない**
- クラウド環境では、ネットワーク設定で `<プロジェクトID>.supabase.co` を許可してもらう必要がある
- 情報提供者として記録するユーザー: 管理者が1人ならその人。複数なら `SIGNBOARD_EDITOR_USER_ID` を設定してもらう
- `node_modules` がなければ `npm install`
- クラウド環境では Node の fetch がプロキシを通らず `getaddrinfo ENOTFOUND <プロジェクトID>.supabase.co` になる。
  以下の `npm run signboard` はすべて `NODE_USE_ENV_PROXY=1 NODE_NO_WARNINGS=1` を前に付けて実行する（手元のPCでは要らない）

### 1. 写真を集める

```sh
npm run signboard -- fetch                        # 空欄のある神社を20社まで
npm run signboard -- fetch --shrine 123,456       # 神社を決めて
npm run signboard -- fetch --pref 13 --limit 50   # 都道府県で絞る
```

`scripts/.cache/signboard/manifest.json` に、神社ごとの「空欄の項目（`blank_fields`）」「入っている値（`filled`）」「写真のファイル」が出る。
すでに反映した写真（`done.json`）は除かれる。もう一度読むなら `--include-done`。

### 2. 写真を読む

manifest の神社ごとに、`photos[].file` の画像を Read で開いて読む。1社に複数枚あれば全部見る（1枚の案内板が分けて撮られていることがある）。
**`blank_fields` にある項目だけ**を拾い、`scripts/.cache/signboard/proposals.json` に書く:

```json
[
  {
    "shrine_id": 123,
    "photo_ids": ["写真のid（manifest の photos[].id）"],
    "fields": {
      "deities": "素戔嗚尊、櫛稲田姫命",
      "founded": "伝・天平年間",
      "annual_festival": "毎年10月第2日曜日",
      "features": "奈良時代に出雲から勧請されたと伝わる。江戸時代には村の鎮守として崇敬を集め、明治に周辺の社を合祀した。"
    },
    "note": "例祭の日付は一部かすれていて「第2」は推定。社格は読めなかった"
  }
]
```

- 何も読めなかった神社も、`fields` を空にして入れておく（`photo_ids` が処理済みになり、次からは出てこない）
- 案内板ではない写真（タグの付け間違い）だったら、`fields` を空にして `note` にそう書く
- `filled`（入っている値）と案内板が食い違うときは、書き換えずに `note` に書く

### 3. 下見してユーザーに見せる

```sh
npm run signboard -- apply scripts/.cache/signboard/proposals.json
```

`preview.md` に「入れる / 入れない（理由）」が出る。神社ごとに入れる値と note を、そのままユーザーに見せて確認してもらう。
直すところがあれば proposals.json を直してもう一度下見する。

### 4. 書き込む

OK をもらってから:

```sh
npm run signboard -- apply scripts/.cache/signboard/proposals.json --write
```

書き込む直前にもう一度今の値を読み、空欄のままの項目だけ入れる（その間に誰かが入れた項目は飛ばす）。
結果は `report.md`。最後に、何社・何項目入れたか、入れなかったものと食い違いの note をまとめて伝える。
マップの絞り込み（ご利益・社格）に出すには、管理者画面の「神社一覧を更新する」が要ることも伝える。

## 注意

- `scripts/.cache/` は git に入らない。クラウド環境ではセッションが終わると消えるので、`done.json`（処理済みの写真）も消える。そのときは、空欄が埋まった神社は自然に出てこなくなるが、何も読めなかった神社はまた出てくる
- 由緒は神社詳細に「ユーザーからの情報提供」として表示される
